**4. THE ARTIFACT-RESIDUAL FRAMEWORK — his core idea.**
> "For a given artifact (or many artifacts) we in theory can compute... the expected amount of the
> artifact that we should see, or do see, as a function of bitrate. IE the less bits we have the MORE
> this artifact appears. It goes to say then that adding MORE bits would REDUCE the amount of the
> artifact we see following the same curve... This is essentially the same as what bpp+ is doing, and
> as such this figure can get added (or subtracted) from the bpp+ measurement or generally blended
> with it. Cause beyond 100, we're saying 'hey this is diminishing returns territory here, we dont
> really need these bits' but BELOW 100 we're saying hey adding bits here would really add quality."

**5. IT MUST BE BIDIRECTIONAL.**
> "importantly it can go both directions its not just a 'shift the entire library in one direction'
> type adjustment"

Concretely: a clean modern film at BPP+ 30 where we *expect* banding and *see* none means the copy
is better than the score says → shift UP. Lots of banding where we expect little → shift DOWN.

**6. THE CURVE GIVES THE MAGNITUDE.**
> "You can compare the ratios at different compressions too to see how it scales / curves as well if
> that makes sense, to predict how much to shift bpp+ by... IE a HUGE bpp+ swing or just a small one"

This is what removes the invented coefficient. BPP+ is denominated in bits, so an artifact difference

> "grain specifically, being an artifact we likely want, IF we can measure it separately from simple

> therefor can compute a curve of grain as a function of bits and calibrate it if theres an
> inflection point etc, IE where the derivative goes from serious improvements to eh marginal ones."

**8. MULTIPLE COPIES IMPROVE THE PER-FILM CURVE.**
> "all of this is for a given film, and if we have multiple datapoints IE multiple copies of the film

# PART 2 — WHAT IS DEPLOYED AND VERIFIED

All three shipped 2026-08-20, verified against prediction, no re-probe needed.

## 2.1 Audio-polluted R — FIXED

`probe-film.sh` takes `srcBitrate` from the video stream when ffprobe reports one and falls back to
the container total otherwise. On the fallback path every audio track sat inside R, so `biasFactor`
came out too small and the correction was **under-applied on exactly the multi-dub/lossless class
§3.2 removed audio from the numerator to stop flattering.**

Measured independently by ffprobing all 898 movies: **361 container-path, 537 already clean.**
Median BPP+ inflation 2.17%, max 8.33% (The Witch), 16 films in the wrong band.

**The fix is scoped, not blanket** — and that distinction is the finding. The obvious one-liner
(subtract `audioBps` everywhere) would have deflated the 537 clean rows by a median 2.1%, max 8.5% —
a *new* error larger than the one repaired. Implementation: `srcBasis` provenance flag emitted by
`probe-film.sh`, backfilled into all 1044 cache entries by `scripts/backfill-srcbasis.js`, and
`videoR()` in probe.js subtracts only on the container path.

Result: 251 movies fell, median −2.35%, all downward, 16 band flips. Controls unmoved (Blade Runner
2049 191, Saving Private Ryan 38, M:I III 46).

## 2.2 Ninety-five seasons had NO BPP+ AT ALL — FIXED

Not a loose score — **no score.** `probe.js` had its own `secs()` requiring `H:MM:SS`, while *arr
reports `30:55` for a sub-hour episode. It parsed as 0, the size-derived fallback went null, `bppOf`
returned null. Movies were immune (always over an hour), so it was invisible on the tab that gets
looked at. `audit.js` has a *second* `secs()` that pads short forms correctly — two parsers for one
field, disagreeing, is what hid it.

All 146 seasons now score. **TV is a different population and must not be pooled with film:** median
86 vs 64, median R 0.89 vs 0.57, 13.7% "wow" against 3.1%.

## 2.3 The pinning curve — REFITTED

`1.337·R^-0.348` flat below 0.59 → **`1.114·R^-0.392` flat below 0.423.** Two independently measured
errors:

1. **The codec floor.** The assumed ×1.06 codec-matching subtraction is really **1.1295** — measured
   by re-running the starvation experiment with `--enc libx264`. 16 points, bit-exact controls,
   bootstrap 95% CI **1.099–1.151**, so the assumed value is *outside* it. The floor is also a
   genuine constant (level 0.5 → 1.1295, level 0.25 → 1.1131). And the x264 arm is the
   **library-realistic** condition — 831 of 898 movies are h264 probed with x265 — so it needs no
   floor subtraction at all and is what should have been fitted.
2. **The axis.** The fit used `R_live`, audio-polluted until the same day, while scoring evaluates
   video-only R. That mismatch alone moves A from 1.337 to 1.255.

Verified exactly against prediction: **median 60 → 64**, bands 606/180/76/36, 810 films moved (median
+5, max +12), **106 band flips, all upward, zero down.**

`PIN_MAX` 2.0 is now unreachable (curve max is ×1.561 at the floor). **Never bump `PROBE_VERSION`
for this** — it is pure re-weighting; bumping would discard 1044 measurements.

## 2.4 The anchoring procedure — RECOVERED AND WRITTEN DOWN

Had never been recorded beyond a phrase, which blocked any verifiable refit:

```
R_anchored = level × R_live × under          under = cx20(base) / cx20(level)
```

It is the *observed* R the library would compute for the starved copy, using the live probe's precise
base complexity instead of the experiment's 3-sample one. **Confirmed by reproduction**: least
squares on `log(under/1.06)` vs `log(R_anchored)`, all 16 points, pre-audio-fix `R_live`, returns
A 1.337 / B −0.349 / rho −0.915 — the shipped constants exactly.

**`under` is deliberately on both sides of that fit.** It is the y-variable and it sits inside the x.
That looks like a mistake and is not: at runtime `biasFactor` only ever sees the *observed* R, already
inflated by the understatement it must predict, so the calibration has to be fitted on the axis it is
evaluated on. Consequence: **rho here is NOT causal evidence** — the self-reference biases it
positive, so a negative rho survives rather than being produced. Use the unanchored own-R rho
(−0.924) for the causal claim.

## 2.5 Banding shipped as a nightly job

`controller/lib/banding.js` + `controller/scripts/probe-banding.sh`. "Audit · banding probe" in the
Jobs tab, weight 99. **8×2s CAMBI clips per unit.**

- **Shares the probe's gates AND its single night budget** — not its own. That is the safety
  property: the box never runs more than `PROBE_NIGHT_BUDGET_MS` of encoding a night no matter which
  job spends it. A second budget would silently double nightly heat (see the 2026-07-09 trickplay

- **Manually triggerable** per decision 13.

- Dataset exposes `cambi` / `cambiMax` / `bands` / `cambiLuma`. **null means UNMEASURED, not clean.**
- `bpp-lab`: banding as a colour and an x-axis (filter removed per decision 12). Unmeasured rows are
  grey and are *dropped* from the banding axis rather than coerced to zero — otherwise ~90% of the

# PART 3 — FINDINGS

## 3.1 CAMBI is a real, independent second axis [SOLID]

**The no-master constraint does not bind.** CAMBI is genuinely no-reference — it keys on flat regions
in a single frame. Only libvmaf's *plumbing* wants two inputs, so both point at the same file. **VMAF
proper is the opposite** and is permanently calibration-only here.

Pre-registered degeneracy tests, |r| > 0.6 would have failed it, replicated on an independent
45-film sample:

| test | first run (n=40) | replication (n=45) |
|---|---|---|
| vs complexity (grain?) | −0.245 | −0.444 |
| vs luma (darkness?) | −0.254 | **−0.022** |
| vs BPP+ (redundant?) | −0.313 | −0.273 |

For scale, `gShare` died at **−0.885** against luma. Plus a working mechanism: among smooth films,
starved copies band **2.33× more**.

**Prevalence:** of 58 films BPP+ calls acceptable, **8 band visibly — 14% (CI 5–23%)**, falling with
the score (6/34 warn, 2/17 ok, 0/7 wow). Two are in the GREEN band with supply *above* transparency:
**Fargo (109, R 1.22)** and **Obsession (103, R 1.12)**. The blind spot is SMOOTH content (median
complexity 0.058 vs 0.102).

## 3.2 Adaptive sampling — FALSIFIED [SOLID]

Blind cut to n=4: **13.2% band flips** against a pre-registered 1% threshold. The *conditional*
stopping rule is wrong **13.3%** of the times it claims to be safe — statistically identical to blind
truncation, i.e. **no discriminating power at all**. And it gets *worse* with more data (14.2% at n=2
→ 17.8% at n=6): the interval narrows faster than the variance estimate improves. Not repairable by
tuning n. **The fixed 8-sample grid was inherited rather than justified; it is now justified.**

## 3.3 JND units for the scale [DIRECTION]

`scripts/jnd-table.js`, doc §6.5. Chain: BPP+ → bitrate ratio (exact) → ΔCRF (measured here,
−13.6%/point) → JND (borrowed, the weak link, 1 JND ≈ 2.5 CRF), plus an origin check against
VMAF-100-at-x264-CRF-22.

It **reproduces a judgement it was not fitted to**: Brennan said unprompted that "dropping from a 100
to a 70 represents a significant drop", and the chain puts 100→70 at **1.6–2.4 JND**. The library
median 64 sits **2.1–3.2 JND** below transparent, which favours open-question-2 reading (a) — the
library is genuinely starved — over (b), the anchor being too high.

## 3.4 Grain gate — measured, NOT shipped [SOLID]

`complexity ≥ 0.30 && R ≤ 1.0`. **All 26 grain-heavy movies qualify**, max R 1.066, 18 bad / 8 warn /
zero above. 12 Angry Men is the proof case: complexity **0.927** (library max, 8× median) on a
**Criterion Remux** — the best transfer sold — and it still reads 72. Deprioritised by decision 11.

## 3.5 Brennan's artifact-residual framework — validated in shape, NOT deployed

See `docs/DESIGN-ARTIFACT-RESIDUAL.md` for the full development. State:

| piece | status |
|---|---|
| Curve **shape** (S, artifact↔bits exchange rate) | **solid** — R² 0.98–0.998 within-run |
| Film's position on its own curve | **solid** — in-run lossless anchor, matches the job |
| artifact-ratio → bits → BPP+ points | **exact arithmetic**, no free constant |
| Reliability shrinkage (Kelley) | **measured** — 0.579 at 4 clips, 0.73 at 8 |
| **Expected artifact (the reference)** | **THE GAP** |

**Two errors of mine that the ladder exposed, both now fixed:**

1. **The naive `1/|S|` scaling is backwards.** It gives a *flatter* responder a *bigger* shift, but if
   banding barely moves with bitrate then banding is *uninformative* about bitrate. Inverse-variance
   weighting gives **shift ∝ |S|·r**. That is why E.T., the flattest responder measured, wrongly took
   the maximum penalty.
2. **Every per-film slope is flatter than the cross-film one** (−0.435 to −1.534 against −1.78) — the
   between-vs-within confound, the identical lesson the pinning work learned.

**Why not deployed:** under the naive form it moved median **10.9 points** with **29 band flips of
85**, and penalised demonstrably clean films — *2001: A Space Odyssey* (cambi 0.32, **below** the
library median 1.08) took the maximum penalty. That is the expected-model failing (R² 0.488), not the
film.

## 3.6 Flat-area fraction — FALSIFIED as the rescue [SOLID]

Right direction (+0.379, more flat area does mean more banding) but it barely helps:

| model | R² | LOO rmse |
|---|---|---|
| **bits only** | 0.468 | **1.2679** |
| bits + cx + luma | 0.477 | 1.2852 |
| old, with `year` | 0.488 | 1.2891 |
| **+ flat, no luma** | 0.499 | **1.2592** |

**Almost all predictive power is `bpp` alone.** Complexity, luma, flat-area and its variances add ~2%
between them.

## 3.7 THE EPISTEMIC BLOCKER — read this before proposing a fix

**Split-half reliability proves the residual is REPEATABLE. It cannot prove the residual is QUALITY.**
A systematically misspecified model produces repeatable errors too, and the two stories — "this copy
is genuinely better/worse than its bits suggest" and "my model is consistently wrong" — predict
*identical internal statistics*. **Nothing measurable inside this library separates them.**

**More sampling does not help.** Misspecification is a bias, not a variance. Raising clips per film
fixed the *reliability* problem (0.579 → 0.73); it makes this one more precisely wrong.

Only an external reference with masters can separate them. Hence CVQAD.

## 3.8 Methodology bugs found in my own ladder (all fixed)

These cost real time and each produced numbers I reported before finding the fault. **Anyone
extending the ladder must know all three.**

1. **Level 1.0 was COPIED while every other level was RE-ENCODED.** So the control sat on a different
   *process* from the treatments — the same class of confound as x265-starving-x265. The Big Sleep
   read 0.0017 copied and 0.1157 re-encoded at 92% of its own bitrate: a **68× step that is
   generation loss, not bitrate.** Fitting through it gave S −11.0 (R² 0.58); excluding it gave −2.1.
   **A 5× error in the one quantity the framework rests on.** Fixed: every level re-encoded.
2. **Changing the CLIP COUNT changes which scenes are sampled** (`T = start + span·k/CLIPS`), and
   banding is intensely scene-dependent. Same film, same level, same encoder: **0.0859 with 4 clips
   vs 0.00716 with 3 — 12× apart.** So a ladder absolute can NEVER be compared against the banding
   job's absolute, or against another ladder run. **Only ratios within one run are meaningful.**
   (This also means my earlier "19× generation-loss offset" claim was a cross-run comparison and does
   not exist.)
3. **No in-run anchor.** Added: CAMBI on the lossless extract, same clips, same run. Reads 0.0017
   against the job's 0.00173 at matching clip count — so the extract reproduces the job exactly when
   geometry matches.

**Corrected result (v2, 6 films, R² 0.979–0.998):** clean films are bitrate-sensitive, already-banded
films are not. The Big Sleep S −2.95 (banding moves 6.4× across 1.3→0.7); Swingers, the library's
worst bander at 7.17, moves **15%** across the same range.

**Convergence test:** Big Sleep re-encodes give 0.0072 at 1.0×, 0.0027 at 2×, 0.0021 flat from 3.5×
onward, against the file's own 0.00173. **The curve converges on the film** — Brennan's "where the
film sits is just the top point on that curve" is correct.

**But note the tautology:** the film being the top of its own curve carries no information about
whether the film is *good*. The information must come from comparing the film to something external.

## 3.9 EXTRAPOLATING THE UPWARD BRANCH — Brennan was right, I was wrong [DIRECTION, promising]

**This is the most promising open thread and it needs further discussion.** Brennan pushed back twice
on my claim that the upward branch is unavailable, and he was correct. The error was conflating two
curves:

- **Curve A** — banding of `re-encode(our file, rate b)`. What the ladder measures. Converges to *our
  file's own* banding as b grows. Tautological at the top, which is what I kept objecting to.
- **Curve B** — banding of an encode of the **original master** at rate b. Our file is one point on
  it; a better copy is another. This is the curve that answers "would more bits help".

**They coincide at low b.** Under hard compression the artifacts introduced swamp whatever was in the
source — Big Sleep at level 0.7 reads 0.2052 against the file's own 0.0017, a factor of 120, so there
is no convergence contamination in the deep-starvation region. So: **fit the shape on the deeply
starved points where A ≈ B, extrapolate upward, and compare the prediction at level 1.0 against the
file's actual measured banding.** That is a real prediction with a real test point, not a tautology.

Tested on the 5-film ladder, fitting only levels 0.7/0.5/0.35/0.25 (all re-encoded, process-consistent):

| film | predicted @1.0 | actual (file) | ratio | reading |
|---|---|---|---|---|
| Goldfinger | 1.2479 | 1.2437 | **1.00** | as expected |
| E.T. | 2.0587 | 1.9110 | 0.93 | as expected |
| Confessions | 1.0260 | 0.8742 | 0.85 | slightly cleaner than typical |
| El Mariachi | 4.7619 | 2.8795 | 0.60 | cleaner than typical |
| Skyfall | 0.0903 | 0.1345 | **1.49** | WORSE than a typical encode at its bitrate |

**The ratios cluster in 0.60–1.49.** Compare that against the cross-film model, whose residuals
spanned roughly 0.3–3.3 and produced the *2001: A Space Odyssey* absurdity. This reference is far
better behaved, and it is **per-film, needs no labels, no metadata, and no external dataset** —
exactly what decisions 1 and 2 asked for.

**Consequence for the ladder design:** my "improvement" to a dense near-1.0 ladder was the WRONG move
for this purpose. The near-1.0 region is precisely where curve A is contaminated by convergence to our
own file. Brennan's original spread (1.0/0.7/0.5/0.35/0.25) was right; deep points are what the fit
needs. Future ladders should carry BOTH: deep points to fit the shape, and the in-run lossless anchor
as the test point.

**Caveats to settle before this is load-bearing:**
- n=5.
- The extrapolation is modest (1.4× beyond the nearest fitted point), but the functional form matters
  and only a power law has been tried. Brennan's "assuming eventual sqrt type behaviour" and a
  saturating form are both worth fitting and comparing on LOO error.
- **The confound to name honestly:** our file was encoded from the master with possibly better
  settings than the `libx264 -preset medium` call used for the ladder. So "cleaner than typical" may
  mean "encoded better than my ffmpeg invocation" rather than "the master was better". That is still
  a real component of file quality, but it is not the same claim, and Skyfall reading 1.49 — a modern
  Blu-ray *worse* than a naive re-encode at its own bitrate — is exactly the case that deserves
  scrutiny before trusting the method.
- CVQAD can settle all of this directly, because it has masters AND a nine-point ladder: fit the low
  points, extrapolate, and compare against the actual high points and the source.

## 3.10 Complexity and banding are orthogonal [SOLID]

raw −0.304 → **+0.010 after removing what bits explain.** Complexity's apparent relationship with
banding is entirely mediated by bits (complexity ↔ bpp is +0.455 — grainy films get given more bits).
This settles decision 3 in Brennan's favour twice: "replace" would discard real information, and the
artifact signal is genuinely *new* rather than a restatement.

## 3.11 Rejected — do not revive

- **Codec-aware pinning refit from banked priors** (research round's P1, "cheapest unblock"): NOT
  VIABLE. Only 52 of 148 priors carry a codec, the hevc arm is 14/19 TV seasons with 6 at exactly
  ×1.000, and understatement spans ×0.59–×2.62 at matched R with several *below* 1.0, which the model
  forbids.
- **Refitting the curve on "clean R"** as report 01 recommended: unnecessary in the form stated —
  `probe-starve.sh`'s own axis is already video-only by construction (clips are `-an -sn`, starved as
  video bits). The refit was needed for a *different* reason (the anchoring uses `R_live`).
- Learned NR metrics (LIQE/FAVER/Q-Align/NR-VMAF), NIQE/BRISQUE — grain-blind.
- KonViD/LIVE-VQC/YouTube-UGC **absolute MOS as weights** — unpaired, the same confound that
  invalidated the 2026-08-13 blind test.
- P.1204.3 in the serving path — no python in the container, and grain-blindness is in the standard.
- Any new additive term in the scalar without a valid label. `gShare` revival. Library-wide ladder cron.

## 3.12 Today's two failures (2026-08-21)

1. **The 8-sample starvation arm never ran on schedule.**
   `while [ "$(date +%-H)" -lt 6 ]` — armed at 23:23, hour is `23`, `23 < 6` is false, so it ran
   **immediately**, into the controller redeploys, and 7 of 8 films died on "container is not
   running". It also overwrote the derived `starve-codec-floor.json` with a 2-point result (primary
   data intact; regenerated). **Fixed:** absolute epoch target that handles the midnight wrap, plus
   transient-docker retries in `starve-experiment.js` that still fail fast on a real measurement
   error. **Not re-armed** — awaiting Brennan.

2. **The banding job measured ZERO units on its first night.** `probeHasFreshWork()` used
   `us.some(u => !unitMeasured(u) || unitStale(u))`. `mv:392` (Air, 2023) fails every sample and
   always will; a permanently-failed unit keeps an *error* entry, so it counted as unmeasured
   **forever** — banding yielded the entire window every night, silently, while the probe spent all
   243 minutes on optional refinement. **This is the exact bug `probePhase()` carries a warning
   comment about.** Fixed by asking **`nextUnit()`** — the authority on what the probe will actually
   do next — instead of reimplementing the question. Verified: `fresh = 0`, `stale = 1`, so one real
   unit clears in ~4 minutes and banding gets the rest.

**The pattern across all of 3.8 and 3.12:** a predicate or control written from *reasoning* instead of
from the thing it was supposed to describe. Every fix was to defer to the authority — an epoch
timestamp, `nextUnit()`, the same encode process at every level.

> - **Bradley-Terry is now the primary label**, MOS only a cross-check. Decision 2's whole point was

>   *worse*, so a positive correlation falsifies the mechanism however strong it is.

# PART 5 — WHAT TO DO NEXT

## THE THREAD TO PICK UP FIRST — and Brennan asked for it to be flagged as needing discussion

**Per-film upward extrapolation (3.9).** He raised it three times and was right each time; it is the
most promising route and it satisfies every one of his constraints — per-film, pixel-measured only, no
metadata, no labels, no external dataset, bidirectional, and self-calibrating in bits.

> "If from our best copy we continually compress into less bits and see more and more banding (or blur
> or other artifacts) then we can construct a curve and extrapolate into bitrate ranges we dont know,
> we can assume if lets say its hyperbolic that itll continue to be, etc etc. We should be able to
> observe this curve per film and extrapolate and say hey I bet there will be even less banding if we
> doubled the bitrate, or maybe 1.25xed it, etc etc which informs where we are bpp+ wise."

What is done: the 5-film test in 3.9, ratios 0.60-1.49, far tighter than the cross-film model.

What is needed to finish the thread:
1. **More films.** n=5. The ladder tool is ready; the design is deep points to fit + lossless anchor
   as the test point.
2. **Compare functional forms** on LOO error — power law vs Brennan's suggested saturating/sqrt form.
   Only the power law has been tried, and the form is what governs an extrapolation.
3. **Settle the encoder confound.** "Cleaner than typical" may mean "encoded with better settings than
   the ladder's `libx264 -preset medium`" rather than "the master was better". Skyfall reading 1.49 —
   a modern Blu-ray *worse* than a naive re-encode at its own bitrate — is the case that most needs
   explaining before this is trusted. Test by varying the ladder's encoder/preset and seeing whether
   the ratio moves.
4. **Validate the extrapolation against CVQAD**, which has masters AND nine bitrate points: fit the
   low points, extrapolate, compare to the actual high points. That gives the extrapolation a measured
   error bar rather than an assumed form.

Only after (2) and (3) should the residual feed a BPP+ adjustment, per decision 10.

## Also immediate (no decision needed)

**1. Let CVQAD finish and run the calibration.** `deepfakesMSU/CVQAD` on HuggingFace, **ungated** — no
CDVL needed. 45 sequences, x264 at nine bitrates each (433–39,381 kbps), 1080p, with **Bradley-Terry
scores from pairwise comparison** plus MOS. Bradley-Terry matters: it measures a *difference*, unlike
the unpaired MOS that invalidated the 2026-08-13 test.

`scripts/cvqad-calibrate.js` runs the decisive test — **does the banding residual predict subjective
score AFTER bits are already accounted for?**
- yes → the framework is real, and the regression slope IS the calibration constant
- no → it was misspecification, and the correction must not ship

It is resumable and runs on whatever has downloaded. **It also has masters**, so it can additionally
validate decision 9 (fit the low bitrate points, extrapolate up, compare to truth) and give the
extrapolation a measured error bar.

**2. Watch the banding backfill.** It should measure units tonight now that the starvation bug is
fixed. Check `atFullPrecision` climbing off 0.

## Then

**3. Replace the cross-film regression with the real machinery.** The literature search turned up what
should have been used from the start: **per-title rate-quality curve prediction** is a mature field —
convex-hull prediction for bitrate ladders, content-adaptive rate-quality curve models, per-shot.
Predicting a title's whole curve from cheap content features is close to solved. That is the
principled replacement for a weak cross-film fit, and it is how per-film S could be obtained for all
1045 units without laddering every one.

**4. Grade `blockMean`/`blurMean`** with the split-half test now that per-clip readings are emitted.
Needs no labels. If either carries real per-film signal, it joins the framework under decision 7.

**5. Grain as the inverse artifact** (decision 7). The hard part is separating grain from noise —
`gShare` died attempting it (doc §11.3) — but the *curve* framing may help where a scalar did not.

## Caution for when several artifacts exist

They must not double-count. Reliability screens each detector individually; **independence needs
checking pairwise.** Blocking, blur and banding all rise together under starvation, so they are
unlikely to be independent — the right treatment is probably one combined residual, not three
additive shifts.

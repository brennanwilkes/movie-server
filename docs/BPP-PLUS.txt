WHAT IT MEASURES, IN ONE LINE, BECAUSE THE NAME MISLEADS. BPP+ is BITRATE ADEQUACY
PER CONTENT: does this file carry the bits ITS OWN content needs? Until 2026-08-27 it
never looked at the picture at all. It now does, a little, through one added term
(section 6) — but the base score is still an argument about bits.

Three consequences that recur:
  - a grainy 1080p scan SHOULD score lower at equal bits, because grain IS screen
    content and genuinely costs more (5.4)
  - a sterling Criterion remux can read "bad" with no better copy in existence (E.3)
  - a file can be adequate for its content and still unwatchable for reasons BPP+ is
    blind to by design — wrong tier, undecodable codec, truncated mux (section 7)

Read "quality score" as ADEQUACY. A rename is a real option and it is Brennan's call.

EVIDENCE TIERS, used throughout:
    [SOLID]      n >= 8, clean internal structure, numbers given in full
    [DIRECTION]  real measurement, too few points to quote a coefficient
    [UNTESTED]   built and/or plausible, never checked against a valid label
    [RETRACTED]  was believed, is not any more. Evidence doc says why.

1. THE PROBLEM AND THE CONSTRAINTS THAT BOUND IT
--------------------------------------------------------------------------------
~3.2 TB of 1080p-and-below film on an 8 TB drive, ~1000 titles. The task is CHOOSING
BETWEEN TORRENT SOURCES:
    UPGRADE    this copy is compromised; is a release on offer meaningfully better?
    DOWNGRADE  this copy spends bits nobody can see; is there a smaller one as good?
Both are the same question in opposite directions and both must be answerable from ONE
NUMBER attached to a file, because that number drives a human sort in the Audit tab.

bpp = videoBitrate / (width * height * fps) is the natural normaliser — it removes
resolution and frame rate. But raw bpp is illegible: the whole library lives between
0.02 and 0.44. BPP+ is that ratio made legible and made per-film.

1.1 LOGICAL CONSTRAINTS — these evaluate a new paper or metric in five minutes, and
almost every published video-quality result fails at least one.

  (a) NO REFERENCE. We never hold a pristine master; the file on disk IS the best copy
      in the building. Every full-reference metric — VMAF, SSIM, PSNR — needs a master,
      so all of them are STRUCTURALLY UNAVAILABLE. This is why "just use VMAF" keeps
      looking attractive and keeps being wrong: VMAF against our own copy measures
      distance from a copy we already suspect.
  (b) THE SOURCE IS ALREADY COMPRESSED — unknown provenance, unknown generation count.
      Netflix's per-title work and Durbha/Bovik both ASSUME a pristine input and that
      assumption is load-bearing in their maths. It is false for us, always.
  (c) THE MEASUREMENT'S INPUT IS OUR COPY. The probe encodes short samples to a NULL
      output; nothing is written, /data is read-only in the container. WE NEVER
      RE-ENCODE MEDIA. The limitation is on the INPUT side and is the origin of the
      pinning problem (5.1).
  (d) THE ANSWER MUST BE ONE SCALAR. Brennan: "I like BPP+ as a single # where I aim to
      upgrade stuff to around 100." Everything bits CANNOT fix is a GATE beside the
      score (section 7), never a term inside it.
  (e) WHAT PRECISION IS FOR — NOT band membership. The bands are a reading aid; a human
      reads 98 and 101 as the same. Precision must support RANKING candidates and a
      rough sense of DISTANCE FROM 100. So THE QUANTITY THAT MUST BE TRUSTWORTHY IS THE
      GAP BETWEEN TWO SCORES. An error moving both scores together is harmless; the
      same error on only one is not. This is the correct lens for every accuracy
      argument here.

1.2 PHYSICAL CONSTRAINTS
  - 4-core NUC that also serves video. Encode experiments run STRICTLY SEQUENTIALLY:
    two heavy jobs measured 93C against a 100C limit.
  - Nightly thermal window 01:00-06:00, 240-min budget. An uncapped nightly task has
    already run the box hot all day once. A manual session is how to run it hard by day.
  - 1080p CEILING. Nothing in the house plays above 1080p, so 2160p is never an upgrade.
  - *** THERE IS NO PROJECTOR RIGHT NOW. *** It died 2026-08-01. The replacement WILL be
    1080p; until it is bought there is no delivery display to judge on, and any protocol
    that requires one is BLOCKED ON HARDWARE, not on Brennan's time.
    Every quality figure gathered before 2026-08-01 was taken through a native-720p
    projector, i.e. while a 44% downscale hid compression and grain alike. Those figures
    understate what a 1080p chain will show. The probe's reference width is already 1920
    (DESIGN-CRF-PROBE) so no re-probing is needed when it arrives.

2. THE FORMULA
--------------------------------------------------------------------------------
    BPP+ = round( 100 * sqrt( bpp / target ) )

    target = complexity * biasFactor(R) * HEADROOM_TARGET
    HEADROOM_TARGET = 1.0        the single global calibration knob
    complexity      = the measured bpp of a CRF-20 encode of THIS FILM (section 4)
    biasFactor(R)   = the source-pinning correction, >= 1.0 (5.1). Do not omit it:
                      applied to every score, worth up to x2.0 on the denominator.

100 IS NOT "AVERAGE". 100 means "this file spends exactly as many bits as a CRF-20
encode of itself would spend". A per-film target, not a library constant.

2.1 WHY THE SQUARE ROOT                                              [DIRECTION]
Measured on this library's content, visible error falls as roughly bitrate^-0.5. The
square root inverts that, so the index is proportional to 1/error:
    200 = about half the visible error of 100   (and 4x the bits)
     50 = about twice the visible error of 100  (and 1/4 the bits)
THE EXPONENT IS FITTED FROM OUR CONTENT AND NEVER INDEPENDENTLY CHECKED. It is the
weakest link in the model. It is also MONOTONIC, so it re-labels every file without
re-ranking any — by 1.1(e), the mildest possible kind of error.

2.2 BANDS
    >= 125  purple "wow"  |  100-124 green "ok"  |  75-99 orange "warn"  |  <75 red "bad"
Carried through from the old linear 150/100/60 via the same square root. THEY ARE NOT
KNEE-DERIVED — reading them as "where the curve bends" reads in something never measured.

2.3 THE SCALE IN A UNIT A HUMAN ALREADY HAS
x265 bitrate runs about -13.6% per CRF point (measured, E.2), so
    CRF_equivalent = 20 - ln(bpp/target) / ln(1/0.85)
    BPP+ 50 -> CRF 28.5   |   100 -> CRF 20.0   |   150 -> CRF 15.0
This converts the headroom question into an answerable one: not "should HEADROOM_TARGET
be 1.0 or 0.57" but "is a CRF-20 encode your definition of correct, or is CRF 23.7".

--------------------------------------------------------------------------------
3. THE NUMERATOR — WHAT COUNTS AS "bpp"
--------------------------------------------------------------------------------
3.1 videoBitrate IS SANITY-CHECKED. *arr's MediaInfo reports a nominal or peak rate for
some HEVC files and is wildly wrong when it does — Challengers was overstated 6.5x,
which painted it purple and filed it as bloat. Anything above the size-derived total is
rejected (1.05 tolerance for container overhead).

3.2 AUDIO IS NOT CHARGED TO VIDEO.                                       [SOLID]
videoBitrate is 0 on ~18% of the library, so bpp falls back to the size-derived total
and every audio track inflates it. Audio is a median 10.2% of the container and up to
65.4%. The bias ran the WRONG WAY: it flattered multi-dub and lossless-audio releases
most — exactly the class we do not want flattered. The audit subtracts what is KNOWN and
never guesses; `bppSource()` reports which case applied. Coverage is 1031/1031.

3.3 HEVC GETS AN EFFICIENCY MULTIPLIER. x265 at the same bpp looks better than x264, so
raw bpp is scaled by X265_EFFICIENCY before indexing.

--------------------------------------------------------------------------------
4. THE DENOMINATOR — THE NIGHTLY CRF PROBE
--------------------------------------------------------------------------------
This is what makes BPP+ per-film. Every night the controller takes 8 four-second samples
across a title, encodes them at CRF 20 TO A NULL OUTPUT, and records the bitrate that
costs. That is `complexity`: what THIS content costs to look right.

WHY CRF: it is a PERCEPTUAL anchor, not a bitrate one. CRF-20 encodes of Casablanca and
Blade Runner 2049 are approximately the same visual quality and cost 3853 vs 1000 kb/s.
"Approximately" is doing real work — fixed CRF is not exactly fixed quality across
content, and whether that residual runs with grain HERE is open question 9.4.

4.1 THE MEASUREMENT THAT KILLED THE FLAT CONSTANT                        [SOLID]
Before 2026-08-06 the denominator was one number, 0.13, library-wide. Measured across
1031 units: median 0.1120, spread 26.8x (min 0.0346 The Father, max 0.9270 12 Angry Men).
The flat constant was wrong by roughly 2x in BOTH directions and SYSTEMATICALLY —
overrating grainy film-stock transfers, underrating clean digital ones. 0.13 was a decent
library-wide average and a poor per-film answer, which is the exact failure mode you
cannot see without measuring. Survives only as the no-probe fallback. -> E.2

4.2 PRECISION MACHINERY
  PROBE_SAMPLES 8 (the floor, not a luxury: scene complexity varies 8.2x WITHIN a film)
  SAMPLES_MAX 16 | POOL_MAX 64 | RSE_GOOD 0.12 | SPREAD_WIDE 6
Pooling only happens when the bytes on disk are unchanged, so a replaced file starts
clean. Nightly priority: first-measurement -> audio backfill -> refinement.

THE SQUARE ROOT HALVES THE ERROR: a relative error e on the target becomes ~e/2 on the
index, so complexity known to +/-24% still yields BPP+ good to about +/-12%.

A POOLING BUG that made error bars shrink on evidence that did not exist was found and
fixed 2026-08-18; sample offsets are now phase-shifted along a van der Corput sequence so
repeat visits land in new gaps. Every pooled cxRSE written before that is too small and
they are not re-derivable. -> E.2

4.3 TV SEASONS are measured whole: episodes sampled, complexity episode-weighted,
all-or-nothing. Median `disagree` 0.241 across 146 seasons; SEASON_DISAGREE_MAX = 0.25
gates the disagreeing ones out of disk-reclamation suggestions. Season numbers are much
softer than movie numbers.

--------------------------------------------------------------------------------
5. CORRECTIONS APPLIED TO EVERY SCORE
--------------------------------------------------------------------------------
5.1 SOURCE PINNING (biasFactor)                                          [SOLID]
`complexity` is meant to be a property of the FILM. It is not, quite.

THE MECHANISM. The probe's input is our copy (1.1c), and CRF 20 cannot ask for detail the
source does not contain. A starved copy measures as an EASY film, its target sinks toward
that copy's own bitrate, and the deficient file scores close to 100. THE WORSE THE COPY,
THE MORE IT FLATTERS ITSELF. By 1.1(e) this is the worst possible shape of error: it hits
the starved side of an upgrade comparison and not the good side.

FIRST PROOF, same film same probe, only the source changed — Paris, Texas, a 2.22 GB copy
replaced by a 12.73 GB Criterion transfer: srcBitrate x6.02 -> complexity x2.33.

THE PREDICTOR IS R = srcBitrate / probeBitrate. R < 1 means the file sits BELOW its own
measured target, so the number is a floor.

THE STARVATION EXPERIMENT settled it: take 8 films the model already trusts, starve them
to 1/2 and 1/4 bitrate, re-measure. Content is byte-identical across levels, so anything
that moved was caused by starvation and nothing else. 8/8 flatten monotonically.
Spearman(R, understatement) -0.924 — and the competing ladder-slope hypothesis is
FALSIFIED at +0.335. -> E.2

The live curve is 1.114 * R^-0.392, flat below R 0.423, capped at x2.0. It rests on an
x1.06 codec floor measured on ONE film and known to be really ~1.13, so the correction
slightly over-corrects; BPP+ is about 3.2% too low on corrected films. Not yet fixed.

5.2 WITHIN A FILM, THE DENOMINATOR CANCELS — AND THIS IS THE DESIGN'S BEST PROPERTY.
Every candidate for a row is scored with THAT ROW'S key, so it gets the row's target and
the target divides out:
    cndPlus / curPlus  ==  sqrt(candBpp / rowBpp)
WITHIN ONE FILM THE RANKING IS PURE bpp. Complexity, biasFactor, HEADROOM_TARGET — the
entire per-film apparatus — cannot move which release wins. It moves the LABEL and the
BAND, not the choice. A wrong denominator CANNOT corrupt a same-film decision.

6. THE PROVENANCE FACTOR — THE ARTIFACT TERM (2026-08-27)
--------------------------------------------------------------------------------
The first term that LOOKS AT THE PICTURE. *** SHIPPED TO PRODUCTION 2026-08-29. *** Live in
controller/lib/artifacts.js (computes P over the whole library) and applied in probe.js
installScoring(), which multiplies the SCORING TARGET by exp(strength*provShare*lambda*P).
PROBE_VERSION was NOT bumped — it is a read-time factor over stored fields.
Every BPP+ on the site carries it: Library, Audit rows, replacement candidates.
The formal spec is docs/BPP-PLUS-FORMULA.md. Full evidence: -> E.4, E.9.

*** IT MUST NOT BE APPLIED IN complexityForKey(). *** That would be CIRCULAR: the surface
regresses each detector on log(cxEff), so P would sit inside its own regressor. complexity
answers "what does this CONTENT cost"; the factor answers "how damaged is this COPY".

BPP+ vs BPP+0 — the subscript is the VALUE OF P, not a version. BPP+ is the full score;
BPP+0 is the same score at P=0, which is exactly what an UNMEASURED unit reports (its
factor is 1.0 by construction). Never re-derive one from the other in a client: the lab
did precisely that for one build and double-counted the term.

THE IDEA. BPP+ judges a file by its bits. Two files with identical bits and identical
content can still differ in quality by a factor of two, because
    artifacts = f(bits, content, ENCODER, SETTINGS, MASTER, GENERATIONS, PREPROCESSING)
and BPP+ sees the first two ONLY. So measure the artifacts, predict what they SHOULD be
from bits and content, and read the difference.

6.1 THE RULE
    P    four artifacts measured per file — banding (CAMBI), blocking, blur, grain kept —
         each residualised against bits + content + codec on a library-fitted surface,
         then summed in the pre-registered re-encode direction (+banding +blocking +blur
         -grain) and standardised to mean 0, sd 1 across the library.
         P > 0 = more damaged than the bitrate explains. P < 0 = cleaner than it explains.
    adj  BPP+ * exp( -strength * provShare * lambda * P / 2 )
    The /2 is the square root. NO CUT-OFFS ANYWHERE: no max, no hinge.

    lambda    1.519   ln(1+anchor)/dPdGen  — but see 6.2, it is not a free constant
    anchor    35.6%   SHIPPED. Honest value ~46% (2.0 CRF) after the 2026-08-28
                      correction, but the anchor is a REPORTED quantity that moves
                      nothing downstream. -> E.7
    dPdGen    0.2005  MEASURED on ladders. One extra re-encode moves P by this much.
    provShare 0.1089  SHIPPED 2026-08-28, MEASURED. Adjusted R2 of P on the bitstream
                      encoder fingerprint: 803 films, p = 0.0025 against a 400-shuffle
                      null, year-controlled (year alone 2.1%, encoder adds 10.7 on top).
                      A LOWER bound — unobserved provenance can only add. Replaces 0.0748,
                      which was sqrt(between-source-label variance fraction), an ESTIMATE
                      long mislabelled as measured. Every adjustment scaled x1.46.
                      NO DOUBLE-COUNTING: 0.1089 is the fraction of the OBSERVED (noisy,
                      4-clip) P's variance that is provenance, so it is already net of
                      sampling noise and must NOT also be shrunk by P's reliability
                      (0.674). -> E.4.5
    strength   1.0    *** A DECISION, NOT A DIAL. Brennan, 2026-08-29: 100%. *** Nothing
                      measures it and nothing was going to — it is the exchange rate
                      between evidence and score movement, i.e. a preference. Shipped as
                      a fixed constant so nobody 'tunes' it. NO FREE PARAMETERS REMAIN.

    THE SHRINKAGE IS f, NOT sqrt(f), and that is a choice of OBJECTIVE, not an estimate:
    f is MSE-optimal per film, sqrt(f) is spread-matching. This score is consumed per
    film, so f is right. -> E.4.4

6.2 *** LAMBDA IS THE RECIPROCAL OF THE BITS-RESPONSE SLOPE, AND THE GENERATION STEP
    CANCELS. *** This is the single most important thing to know before touching any
    constant above. The anchor is NOT independent of dPdGen: it came from the crossed
    ladder as exp(B/A)-1, with B = dP/dgen and A = |dP/dlog bpp|. So ln(1+anchor) = B/A,
    and whenever the same generation step sits in both places,
        lambda = (B/A) / dPdGen = 1/A
    Check: A = 0.6555 gives 1/A = 1.526 against the shipped 1.519. It is an identity.
    CONSEQUENCE: the only quantity lambda depends on is how fast P responds to BITS. The
    generation measurement enters, cancels and leaves. Anyone "improving" dPdGen alone
    changes lambda by an arithmetic accident, not by a finding — see trap 16. A better
    generation number belongs in the ANCHOR. -> E.6, E.7

6.3 STATUS — AND A CORRECTION THAT CHANGES WHAT THE PROBLEM IS
    *** P IS REPRODUCIBLE. THE "0.106" FIGURE WAS A DIFFERENT STATISTIC AND HAS BEEN
    CONFLATED WITH RELIABILITY THROUGHOUT THIS PROJECT. *** Measured directly, with no
    model, by splitting 12 clips into disjoint 6/6 halves and computing the FULL
    four-detector P on each, averaged over all 462 distinct splits (n=54 films):
        6-clip P   0.756      12-clip P  0.861      4-CLIP P (SHIPPED)  0.674
    Three independent routes agree: this direct split-half, the earlier corr(P) = 0.693
    between two 4-clip reads, and a variance model at 0.651-0.681. NONE agree with 0.106.
    What 0.106 measures is the split-half across DISJOINT DETECTOR PAIRS — "do the four
    detectors share a common factor?" — which is a question about whether P measures ONE
    THING, not about whether two reads agree. -> E.9.5

    SO THE REMAINING PROBLEM IS VALIDITY, NOT PRECISION. P reproduces itself well enough
    to rank films; what is unclear is that the thing it reproduces is provenance rather
    than a mixture. That needs a different fix from "more clips", and the project spent
    considerable effort on the wrong one.
    Scene sampling is still a REAL shared nuisance — all four detectors read the same
    clips and the sampling direction points along the signal — it is simply not large
    enough to make the ordering unusable. -> E.9.4
    THE LAST FAILING PRE-REGISTERED CHECK IS NOW CLOSED (2026-08-28). Re-run with the
    encoder fingerprint as a SECOND field contrast and a worst-of-two statistic:
    96/20000 random directions beat the pre-registered one on BOTH, against a bar of
    100/20000 set before the number existed. It PASSES BY 4% — narrow, and quote the
    margin. Two things strengthen it: the joint rate is less than HALF what independence
    of the two contrasts would predict (210/20000), and the physics direction ranks 1 of
    16 sign patterns. -> E.4.3b
    *** P IS AN INDEX, NOT A MEASUREMENT OF ONE HIDDEN QUANTITY. *** (2026-08-28) The
    question the "0.106" was really asking has now been answered properly. Factor-analysed
    with the shared-clip nuisance SUBTRACTED (simulated from the 60-clip films, not
    approximated — clip-level cambi reaches 1.7e-9, so the delta-method shortcut is
    unusable), the spectrum is
        lambda  1.399  1.080  0.814  0.708      independence would give 1,1,1,1
    Pre-registered before the number existed: ONE THING at lambda1 >= 2.0, INDEX at < 1.5.
    The common factor is REAL (0/2000 under an independence null) but WEAK — 35% of the
    variance against a floor of 25%. Robust: the verdict holds from 0x to 1.5x the nuisance
    correction, and 2x is impossible.
    THE STRUCTURE IS 3+1. Banding, blocking and grain are equicorrelated at r = 0.191
    (spread 0.062); BLUR IS ORTHOGONAL to all three (mean r 0.045) while carrying a quarter
    of the weight. PC1 communality: banding 48%, blocking 40%, grain 46%, BLUR 5.5%.
    CONSEQUENCE FOR THE LANGUAGE: "the provenance FACTOR" claims a latent quantity is being
    estimated. It is not. P is a composite damage INDEX in a pre-registered direction —
    legitimate, still carrying both field contrasts, still the right thing to shrink by
    provShare, but an index. And two standing puzzles are now EXPECTED rather than defects:
    the 0.674 reliability, and re-weighting being unidentifiable. -> E.9.7
    RE-WEIGHTING THE FOUR DETECTORS DOES NOT HELP: the optimal direction wins
    out-of-sample (0.623 -> 0.756 at 4 clips) but is NOT IDENTIFIED — cos between two
    half-sample fits is only 0.549 — and it responds to a real generation LESS
    consistently than the pre-registered direction (21/24 against 24/24). This is now
    understood: a near-spherical covariance has no preferred direction to find, so the
    non-identification is BY CONSTRUCTION and not for want of data. -> E.9.6, E.9.7
    DO NOT ARGUE FROM A DETECTOR'S FIRING RATE. Blocking crosses its threshold on a median
    0% of scenes even at 60 clips, and that was read across this project as "a detector
    carrying a quarter of the weight contributes almost no signal". THAT INFERENCE IS
    WRONG: P uses the continuous residual LEVEL, not the threshold-crossing FRACTION, and
    blocking loads normally (0.536, communality 40%). -> E.9.7
    SOURCING block/blur FROM THE NIGHTLY PROBE WAS TRIED AND REJECTED (2026-08-28). It was
    argued to be a free win — better sampled, and it would split the shared clip draw. It
    FAILS the arbiter at 355/20000 against the bar of 100, because the WEB-vs-Bluray gap
    collapses 0.2088 -> 0.1480 (the encoder contrast improves, and worst-of-two correctly
    refuses the trade). The premise also violates its own attenuation bound: the two
    sources' blur residuals correlate 0.609 where sqrt(0.404 x 0.664) = 0.518 caps it, so
    at least one of those reliabilities is understated. Baseline restored, verified at
    max |dP| = 0. -> E.11.1
    The GROUP-LEVEL results are unaffected and remain correct, because a zero-mean
    within-file nuisance adds variance to a group mean without biasing it. -> E.4.2

    Effect on the library: p05 -9.1%, p95 +9.9%, worst +-19%, median 67 -> 67, and 21% of
    the units near the 100 line change side. -> E.4.6

6.4 *** THE STRUCTURAL LIMIT, AND IT MATTERS MORE THAN ANY NUMBER ABOVE. *** P is
    standardised to mean zero across the library, so the adjustment is ZERO-SUM and CANNOT
    MOVE THE MEDIAN. It answers "which files are worse than their bitrate suggests,
    RELATIVE TO THIS LIBRARY". It says nothing about whether the library as a whole is
    well provisioned — if every file here were re-encoded garbage, P would still centre on
    zero and nothing would move. Moving the whole scale is a DIFFERENT question and the
    absolute artifact THRESHOLDS are the tool for it, because they owe nothing to this
    library. See 9.1.

6.5 DETAIL LOSS — A VALIDATED INSTRUMENT, NOT A TERM. NOT IN THE SCORE. -> E.8
    The covering set has a hole: banding, blocking, blur and grain are all "something
    appeared" detectors, and detail loss is smooth degradation with no artifact signature.
    Blur cannot fill it — it is a pure log(bits x content) function, ORTHOGONAL TO BPP+'s
    log(bits/content) BY CONSTRUCTION, so no amount of data could ever have fixed it.
    Grain is the same. The hole is not merely a gap: complexity both DEMANDS bits and
    MASKS artifacts, so every detector we own pushes the complexity exponent DOWN and the
    one effect that would push it UP has no instrument. Every calibration is therefore
    biased toward "fewer bits needed" and would return that answer even if it were false.
    THE INSTRUMENT that fills it is perPoint = d log(bitrate)/d CRF, measured by encoding
    clips at CRF 16/20/24/28 — a bitrate-domain measure of how much destructible detail a
    file still holds. Reliability 0.945 at 6 clips; separates content from damage at 11.8
    SE; survives a gblur specificity leg at 19% against a 70% kill line; 67% non-redundant
    with BPP+. It is NOT WEIGHTED INTO ANYTHING: the exchange rate from its residual to a
    bitrate-equivalent is unmeasured, and the obvious conversion is the same transfer
    assumption that inflated the anchor 4.6x. Per-film READINGS are trustworthy today;
    per-film ADJUSTMENTS are not computable. -> E.8.5, E.8.6, E.8.8, E.8.9

    I FIRST WROTE THIS UP AS "P COUNTS GRAIN TWICE". THAT IS TOO STRONG — Brennan pushed back
    and he is right. Correlated indicators are only double-counting when the correlation is a
    shared NUISANCE. When it is shared SIGNAL, summing them is averaging, which is the whole
    point of having four. Here it is mostly signal, for a reason specific to what P is for:
    P scales the BITRATE TARGET (target = complexity * artifactFactor), so the question it
    answers is "does this file need more bits or is it fine as it is" — a question about the
    PERCEPTUAL OUTCOME. And grain genuinely fixes banding; dither is the standard CURE for it,
    not a trick that blinds the detector. A grainy film with no visible banding really has none.
    Grain is good provenance and absent banding is good provenance, both true at once, both
    earned. The measurement agrees: if this were nuisance, decorrelating would reorder the
    library, and Spearman is 0.9955.
    THE NARROW CASE THAT DOES SURVIVE: grainy AND starved. There the grain bonus is real but
    the low cambi is not evidence about the ENCODE — the same encoder on a clean digital source
    might band badly. That is a gate, not a reweighting, and it is already filed as #52
    ("grainy and under-provisioned" — a gate, not a term).
    NOTE THE SIBLING RULING, AND WHY IT DIFFERS: 6.6's adequacy term deliberately SATURATES so
    grain buys no credit through banding. Correct there, because adequacy asks a THRESHOLD
    question ("is this at the elbow"). P asks an APPEARANCE question. Same correlation, opposite
    correct treatment — do not "fix" one to match the other.
    AND THE EXPERIMENT THAT LOOKS DECISIVE AND IS NOT: adding synthetic grain to a banded clip
    and watching cambi fall. Both readings predict exactly that. It would prove nothing.
    SIZE OF THE PROBLEM — SMALL. P is re-standardised library-wide, so the variance inflation
    cancels and only the ORDERING is affected. Rebuilding P from ZCA-whitened residuals (the
    order-free decorrelation) moves BPP+ by a median 0.51%, p90 1.25%, max 4.22%, Spearman
    0.9955. Biggest single mover Lessons in Chemistry S01 at +4.2% (grain 0.950, cambi 0.00).
    NO CHANGE RECOMMENDED on this evidence — record it, do not act on it.
    AND A METHOD NOTE. My first pass used CHOLESKY whitening and reported median 1.44% / max
    14.61%, ~3x larger. Cholesky is TRIANGULAR: w = L^-1 z leaves the first detector untouched
    and strips the last of everything the other three explain, so which detector pays is decided
    by the order they happen to be listed in — an arbitrary choice presented as a result. ZCA is
    the whitening that treats all four evenhandedly. If a decorrelation is ever adopted, it must
    be the symmetric one, and the 3x gap between the two is the cost of getting that wrong.

7. WHAT BPP+ IS DELIBERATELY BLIND TO — THE GATES
--------------------------------------------------------------------------------
By 1.1(d), everything bits cannot fix is a gate beside the score, never a term inside it.
Folding corrupts a number that means one clean thing.

  SOURCE TIER      a remux and a WEBRip can share a BPP+. Tier is a CEILING bits cannot
                   raise. Remux > Bluray/Web-DL > WEBRip > HDTV > DVD > SD/CAM.
  RESOLUTION       1080p ceiling: 2160p is never an upgrade in this house.
  CODEC/PROFILE    10-bit HEVC the hardware cannot decode is worthless at any score.
  INTEGRITY        truncated mux, wrong runtime, missing audio.
  EDITION          theatrical vs extended is a preference, not a quality axis.
  RE-ENCODE        a re-encode of a good source is worse than its bits suggest — this is
                   exactly what section 6 now measures rather than gates.
  GRAIN            grain IS content and genuinely costs bits (5.4 in the evidence doc).
                   Grain also BLINDS the artifact detectors: banding fires on 28.4% of
                   smooth content and 9.0% of grainy. State it as "grain blinds", never
                   as "smoothness helps".

8. HOW THE SCORE IS ACTED ON
--------------------------------------------------------------------------------
The Audit tab is where BPP+ becomes decisions. Precision is the stated goal: neither false
positives (flagging good copies) nor false negatives.

8.1 OVER-SUPPLY (the Disk section)
    OVERSUPPLY_R = 2          flag only past 2x transparent
    OVERSUPPLY_MIN_GB = 2     below this it is not worth a human's attention
    overBytes = bytes * (1 - OVERSUPPLY_R / R)
OVER-SUPPLY IS MEASURED ABOVE THE 2x FLOOR, NOT ABOVE TRANSPARENCY. An early report called
a Westworld swap "cutting into the picture" citing 0.24 GB of surplus; the real surplus
above transparency was 8.0 GB (44%). BPP+ already IS a surplus measure — a candidate at
100 lands ON the transparency anchor, not below it.

8.2 UPGRADE ELIGIBILITY
    upgradeEligible = short || unprobed || reenc || bppPlus < UPGRADE_BPP_PLUS_MAX
Serve-time filtering in rankCands() applies the gates, which avoids bumping
VERDICT_VERSION and re-verifying the whole library for a filter change.

9.1 *** WHERE SHOULD 100 SIT? *** The library median is ~67 and Brennan has long suspected

      - Visible banding falls monotonically with BPP+ across every band and inside every

9.1a *** THE SCENE FRACTION IS ITSELF A CUT-OFF, AND IT WAS DISCARDING MOST OF THE
    MEASUREMENT. *** (2026-08-28) The design rule forbids cut-offs. The blend rule obeys it;
    the threshold track did not — "fraction of scenes past T" thresholds every scene and
    then counts, so a scene at 2.80 and one at 28.0 are identical on their own side of the
    line. MEASURED ON THE SAME FILMS AND THE SAME CLIPS, the reliability of one 4-clip read:
        detector    counted fraction   smooth mean of log(L/T)
        banding          0.441                0.695
        blocking         0.041                0.809      <- 19.6x
        blur             0.400                0.651
        grain            0.522                0.891
    The smooth statistic at 4 clips matches the counted one at 12-30, so E.9.6's "24 clips
    is the operating point" is a fact about the STATISTIC, not about sampling. T IS NOT
    DROPPED — it is demoted from a GATE to a UNIT, sitting at log(L/T) = 0, so the external
    calibration is retained exactly. -> E.9.8

    BLOCKING WAS NEVER A WEAK DETECTOR. It has been described throughout this project as
    firing on almost nothing and therefore contributing almost nothing while carrying a
    quarter of P's weight. That was a fact about thresholding a quantity living below its
    threshold, not about the detector: on the same data its smooth reliability is 0.809,
    better than any other detector's counted fraction at any clip count tested. Three
    independent lines reached this correction on one day — the factor analysis (E.9.7), the
    level-vs-fraction distinction, and this. -> trap 23

    AND THE OBVIOUS REPAIR DOES NOT WORK, which is the more useful half. Brennan's "5% of
    scenes" criterion is intrinsically a count, so the natural fix is to estimate the count
    smoothly as Phi(mean/sd) of the per-clip log-excess. It is UNBIASED (median 0.3-1.2pp,
    worst film 9.3pp) but only helps banding (1.82x); blur and grain gain 1.04-1.05x. The
    transform needs an SD estimated from 4 clips, and that is noisy enough to spend the
    advantage. THE FRACTION IS THE LOSSY OBJECT, and it cannot be recovered by estimating
    it more cleverly. DECISION: report the smooth log-excess AS the number — which is what
    the design rule asked for — and quote a fraction only for human communication, with its
    error bar, never as the thing the score is built from. -> E.9.8

    AND THE ANSWER IS CURRENTLY BIASED. Every artifact we can measure is one that
    complexity MASKS, so all of them argue for fewer bits; the effect that argues for more
    — detail retention — had no instrument until perPoint (6.5) and is still not weighted.
    Until it is, "the artifacts say we need fewer bits" is an answer this setup would
    produce whether or not it were true. -> E.10.1

MEASUREMENT
  0. *** ASK THE FILE, NOT THE UNIT — AND CHECK THE UNITS OF THE ANSWER. *** The four bugs
     of 2026-09-01 (6.5b) were all one of two shapes, and each survived months in production
     because the wrong answer was a LEGAL value:
       (a) a unit field that never existed. `u.codec` and `u.runtimeSec` are not set by
           buildUnits(); `|| null` and `|| 0` turned both into silent defaults, and `|| 0`
           on a duration routed the whole job onto a fallback clip grid. Before reading
           ANY property off a unit, grep buildUnits() and confirm it is written there.
       (b) a filter that reports in NATIVE PIXEL UNITS. signalstats YAVG is 0-255 at 8-bit
           and 0-1023 at 10-bit, so grain read 4x high on 49 files. blockdetect/blurdetect
           are likewise resolution-sensitive (6.5c). If a metric is not dimensionless,
           normalise the input — do not correct the output.
     THE DIAGNOSTIC THAT WORKS: cross-tabulate every detector against things that CANNOT
     affect picture quality — bit depth, container, resolution, source label. A split there
     is a measurement bug until proven otherwise. It is how all four were found.
  0b. *** SOME OBVIOUS TESTS ARE VACUOUS BY CONSTRUCTION. *** corr(residual, log bpp) and
     mean residual by codec are EXACTLY zero however broken the data is, because OLS
     residuals are orthogonal to every basis column and `lb`, `hev` and `hev*lb` are
     columns. Two separate investigations in 2026-09 nearly closed on that fake null.
     Use group cross-tabs and within-film controls instead.
  1. HOST ffmpeg IS 4.2 AND HAS NO blockdetect/blurdetect. It fails SILENTLY. Use

  2. `-vf` IS AN OUTPUT OPTION and must precede the output URL.
  3. I-FRAMES ARE INSERTED AT SCENE CUTS, so a naive iRatio reports "compression" where

  4. THIS BOX HAS 4 CORES. Run encode experiments strictly sequentially — two heavy jobs

  5. A SINGLE top/docker-stats/iostat SAMPLE LIES. Sample properly before claiming load.
  6. AN EXPERIMENT USING FEWER SAMPLES THAN THE NIGHTLY PROBE CANNOT BE COMPARED TO IT on

  7. LADDER ABSOLUTES DO NOT TRAVEL BETWEEN RUNS. Only slopes do.

ANALYSIS — every one of these cost real work
  8. CHECK A NUMBER AGAINST AN EXTERNAL BOUND BEFORE CHECKING ITS STANDARD ERROR. A tight
     error bar on an implausible number killed a whole construction here.
  9. CONVERT A CORRELATION INTO AN EFFECT SIZE against a spread that matters. Three
     detectors "tracked luma" at r ~ 0.6 while moving under 0.5% of their own spread.
 10. CHECK THE COUNTS BEHIND A PERCENTAGE. A trend was reported here on 41 films spread
     across five bands.
 11. OLS RESIDUALS ARE ORTHOGONAL TO THEIR REGRESSORS BY ARITHMETIC. "corr(residual, bpp)
     = 0.000" is not a passing control, it is a tautology.
 12. COMPARE A RESIDUAL AGAINST THE PREDICTION, never against the observed value it is a
     component of. Doing the latter manufactures correlation.
 13. A MAX IS A CUT-OFF. So is a hinge. The design forbids both, and both were found
     hiding in an earlier version of the blend.
 14. `R` IS NOT THE RATIO BPP+ DIVIDES BY. Treating it as one produces a discrepancy that
     looks exactly like the model failing to fit its own data.
 30. A PRE-REGISTERED RULE IS ONLY AS GOOD AS ITS STATISTIC — AND max/min IS NEVER THE RIGHT
     ONE. Task 107 registered "GT grain range >= 2.0x reopens the grain leg" before measuring,
     honestly and in advance. It measured 2.76x and said REOPEN. But max/min is an
     EXTREME-VALUE statistic: dropping the single lowest clip took it to 1.81x, below the bar,
     and the spread that actually determines an interaction's SE (p90/p10) was 1.47x — barely
     moved from the proxy's 1.42x. The substantive test agreed: SE(phi1) 0.474 in exponent
     units against a 0.47 bracket, still underpowered. ONE CLIP FLIPPED A PRE-REGISTERED
     VERDICT. Register on a ROBUST quantity that DRIVES the decision — sd, or an interquantile
     spread. Ask before registering: "how many single observations could flip this?" -> 9.0x
 35. A BOUND IS NOT A POINT, AND PULLING TOWARD THE ANCHOR IS WRONG ON ONE SIDE. The adequacy
     term pulls toward 100. For a DIRTY film that is backwards: dirty means "below the elbow", and
     100 IS the elbow, so a dirty film sitting AT 100 had nowhere to fall. Office Space (banding
     5.36, ~2x threshold, BPP+ 100) moved -0.2 points. The dirty side needs a target strictly
     BELOW 100. Ask what the evidence BOUNDS, not what it points at.

 34. DO NOT FIT A LOGNORMAL TO A DETECTOR THAT READS EXACTLY ZERO. CAMBI reads 0 on most clips and
     spikes on one. A lognormal prediction interval scored The Empire Strikes Back at +0.88
     "clean" while it contained a clip at 3.47, over the visibility threshold. Per-clip smooth
     votes, then averaged, handle the shape; a distributional fit does not.

 33. A FIT WHOSE OUTCOME IS ANOTHER ESTIMATOR'S ANSWER IS CIRCULAR. Regressing banding on
     "is BPP+ >= 100" measures agreement between two estimators, NOT the physics either one is
     estimating. It saturated at 0.48 even 30x below threshold (tracking the 16% base rate) and
     gave GRAINLESS clean films 19% less credit than grainy ones. When the label is a model
     output, the fit answers a question about the model.

 32. THE SAME NUMBER MUST BE DERIVED FROM THE SAME INPUTS ON EVERY SURFACE, AND "close enough"
     IS NOT A DEFENCE. The Library tab derived a file's duration from *arr's `runtime` (INTEGER
     MINUTES) while probe.js and audit.js parsed MediaInfo's exact `runTime`. Shawshank: 142 min
     vs 142.6 — a 0.41% shorter duration, so a 0.41% higher bitrate, so bpp 0.14829 against
     0.14769, so **BPP+ 89 on the Library tab and 88 on the Audit tab for the same file**.
     A one-point gap sounds harmless. It is not: a person checking one surface against the other
     cannot distinguish it from a real change, which makes BOTH surfaces untrustworthy for exactly
     the comparison they exist to support. Found by Brennan noticing 88/89/88 across three views.
     Fixed by making MediaInfo the duration source everywhere, *arr's minutes only as a fallback.
     THE GENERAL RULE: when two surfaces show the same quantity, they must share the DERIVATION,
     not merely the formula. Check the inputs, not just the arithmetic.

 31. DO NOT CLOSE A TASK ON PARTIAL DATA FROM THE RUN THAT WOULD DECIDE IT. Task 73 was closed
     at 10:52 citing "at 24/41 the range is 1.72x"; the completed run read 2.76x and the
     closure had to be reversed eight minutes later. This is trap-adjacent to 9.0s (a
     correction extrapolated from n=1 that overshot 2x) and it is WORSE, because it landed in
     a DECISION rather than an estimate. If a running job bears on a decision, the decision
     waits for the job. Both times the answer happened to survive; that is luck, not method.
 28. A LONG JOB MUST PROCESS ITS UNITS IN AN ORDER THAT SPREADS THE REGRESSOR, NOT SORTS
     IT. vmaf-ladder.mjs was written to walk sequences in ASCENDING complexity, which is
     fine if the run completes and worthless if it does not: a truncated ascending run
     covers only the least complex units, and 9.0m already measured what a slope fitted on
     no regressor range does — it attenuates toward zero and can cross it (`ugc` returned
     a = -0.135 on sd(log cx) 0.640). Bisection order (median, then quartiles, then
     octiles) makes EVERY PREFIX a spread sample. Measured on the 41 GT masters, sd(log cx)
     of the first 8 processed: ASCENDING 0.442, BISECTION 0.951, full set 0.948. Ask of any
     resumable job: "if this dies at 30%, is what I have still analysable?"
 29. `pkill -f 'foo.sh'` KILLS THE SHELL THAT RAN IT, because that shell's own command line
     contains the pattern. This is trap 15/21 in a third costume and it cost a launch cycle
     here: the compound command died at the pkill, so the replacement job it was supposed to
     start never started, and only a follow-up check caught it. Bracket the pattern
     (`'[f]oo.sh'`) or use `pkill -f --older 1`. NEVER assume a compound command continued
     past a pkill — verify the thing it was meant to launch is actually running.
 26. A MEASUREMENT MUST LIVE IN THE SAME COORDINATE SYSTEM AS THE COVARIATE IT IS
     REGRESSED AGAINST. cxEff is measured at width 1920; the first VMAF rung run compared
     at each master's NATIVE geometry (up to 3840x1620), which is standard VMAF practice
     and wrong here — the fitted exponent would have been part resolution effect. Measured
     cost: 6.28 VMAF points on one clip, against a total cross-content signal of 6.86.
     THE ERROR WAS 92% THE SIZE OF THE SIGNAL. Before regressing anything on the probe's
     output, check that both sides came out of the same pipeline at the same geometry.
     -> 9.0o
 27. A LOSSLESS INTERMEDIATE IS NOT AUTOMATICALLY A NO-OP. Introducing an FFV1 copy of a
     master — lossless, with pix_fmt/range/dimensions verified identical — moved a VMAF
     score 11.78 -> 11.01 on a clip where the rescale was a no-op. Cause never diagnosed.
     If a preprocessing step "cannot" change the numbers, VERIFY THAT ON ONE FILE before
     applying it to a corpus, because the resulting shift is a per-sequence offset and
     those bias cross-sequence slopes. -> 9.0o
 15. `pgrep -af 'node scripts' | grep ...` SELF-MATCHES its own command line. Use
     `ps -eo args | grep -E '^node scripts/'`, or bracket the pattern in a wait loop.
 16. THE CONSTANTS IN lambda ARE NOT INDEPENDENT. anchor was DERIVED from dPdGen, so
     lambda = 1/|dP/dlog bpp| and the generation step cancels. Re-measuring dPdGen and
     substituting it alone changes every shipped adjustment by an arithmetic accident, not
     by a finding. A better generation number belongs in the ANCHOR. This was caught with
     the substitution already written down (it would have scaled the rule by 0.40x).
 17. A SCENE-LEVEL THRESHOLD APPLIED TO A FILM-LEVEL MEAN ANSWERS THE WRONG QUESTION, and
     is wrong by ~3x here: banding reads 20% of films by the 4-clip mean and 67% by "any
     clip". The published CAMBI threshold is a scene number. Averaging first destroys
     exactly the excursions the threshold exists to catch.
 24. A VERDICT FUNCTION MUST TEST "IS THIS INFORMATIVE AT ALL" BEFORE IT TESTS "DID IT
     PASS". exponent-bracket.mjs printed "BRACKETED — task 99 is no longer blocked" on an
     argmax sitting on the search boundary with a bootstrap CI covering the ENTIRE swept
     range. The uninformative branch sat below the pass branch in the if-chain, so pure
     noise announced a pass. Order the branches: uninformative, then fail, then pass.
     *** COMMITTED A THIRD TIME, 2026-08-28, in blur-weight-profile.mjs. *** It branched on
     `best.c < shipped.c` and printed "that is a real improvement" for 17 vs 15 — a 0.35 SE
     difference on Poisson counts. THREE COMMISSIONS OF THE SAME TRAP, TWICE AFTER WRITING
     IT DOWN. Prose in a traps list does not prevent it; only a computed separation test in
     the script does. THE DEFENCE, USE IT: when the statistic is a COUNT, the difference of
     two counts has SE ~ sqrt(a+b), and anything inside 2 of those is a TIE regardless of
     which number is lower. Compute that SE and branch on it before naming a winner. The
     same shape applies to any argmax over a swept profile: report the FLAT BAND, not the
     grid point that happened to be lowest.
 23. DO NOT JUDGE A DETECTOR BY HOW OFTEN IT CROSSES ITS THRESHOLD. Blocking crosses on a
     median 0% of scenes even at 60 clips and was written off across this project as
     contributing almost nothing. It loads normally on the common factor (0.536, 40%
     communality) and its smooth reliability is 0.809 against 0.041 for its own counted
     fraction. A detector that lives below its threshold is still measuring; thresholding
     is what destroys the information. -> E.9.7, E.9.8
 18. YOU CANNOT MEASURE A 5% RATE WITH 4 SAMPLES. Rule of three: zero exceedances in n
     clips bounds the true rate below only 3/n, so n=4 bounds it at 75%. Any "this film is
     clean" claim from the 4-clip backfill is nearly vacuous. Resolving a 5% target needs
     ~60 clips per film — which is only ~2 minutes of video, so this is a cheap fix and
     not a modelling problem.
 19. GRAIN'S EXCEEDANCE TEST RUNS BACKWARDS. Grain is a RETENTION measure with direction
     -1: it is visible damage when grain is BELOW 0.905, not above. The same sign slip
     already inverted the denoise axis once and was caught only because the result was
     physically impossible.
 20. DO NOT PUT A VERDICT BOUNDARY ON A RAW QUANTITY THAT LANDS NEAR IT. The gen1->gen2
     analysis branched on absolute B2 with a cut at 0.15. At n=18 B2 was 0.1487 and it
     printed CONTAMINATED; at n=24 it was 0.1547 and the SAME SCRIPT printed CLEAN —
     while the measurement moved 0.006, well inside its own SE of 0.011. Branch on the
     RATIO to the predicted value instead (0.49x then, 0.51x now, stable). A stable
     number can manufacture an unstable conclusion if the threshold sits on top of it.
 21. A CHAINED WATCHER SELF-MATCHES THROUGH THE COMMAND IT IS WAITING TO RUN. This one
     cost 37 minutes and was MISDIAGNOSED TWICE. A watcher written as
         until ! ps -eo args | grep -q "[g]eneration-step2"; do sleep 60; done; \
           node scripts/generation-step2-analyse.mjs; node scripts/next-job.js
     never exits — because its OWN command line contains "generation-step2-analyse.mjs",
     which the bracketed pattern still matches. Bracketing protects the PATTERN, not the
     rest of the line. It looked like the watcher had died (the box was idle and nothing
     logged); it was actually alive and spinning, and would have launched a DUPLICATE
     heavy job if ever released. Launch jobs directly with `nohup node ... &`.
 22. `grep -v grep` DOES NOT ISOLATE A PROCESS WHOSE OWN COMMAND CONTAINS "grep". Hunting
     the watcher above with `ps | grep 'until ! ps' | grep -v grep` returned NOTHING,
     because the watcher's cmdline contains `grep -q`. Use awk with a self-excluding
     pattern instead: `ps -eo pid,args | awk '/bash -c until/ && !/awk/ {print $1}'`.

12. HOW TO ADOPT A NEW MEASUREMENT
--------------------------------------------------------------------------------
The order below is not bureaucracy; step 3 is the one that was skipped and it cost the
only subjective label this project ever had.

  1. MEASURE IT ON A PILOT, NOT THE LIBRARY. A stratified subset answers "does this vary
     in a way that could matter" for a fraction of the cost.
  2. DECIDE WHETHER IT IS EVEN A PER-FILM QUANTITY before building per-film machinery.
  3. *** VALIDATE BEFORE WEIGHTING. NOT OPTIONAL. *** A measurement that has not been
     shown to predict something you care about must not enter the score, however
     plausible its mechanism.
  4. USE PARTIAL DATA WHERE YOU HAVE IT. Brennan: "I prefer accuracy. If we have it for
     some, use it." Audio coverage grew from 8 films to 1031 and every film it reached was
     more accurate for it.
  5. ONLY THEN cron, UI, playground — in that order. PROBE_VERSION must NOT be bumped for
     a re-weighting; it invalidates the expensive measurement for a cheap reason.
  6. VERSION THE SCORE ITSELF when the formula changes, so historical numbers stay
     interpretable.
  7. UPDATE THIS DOCUMENT IN THE SAME CHANGE (section 0).

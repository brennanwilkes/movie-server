# PART 1 — THE IDEA, AND WHY IT IS NOW WORTH BEING EXCITED ABOUT

BPP+ answers **"is this file big enough?"** That is a *proxy*. The thing we actually care about is
**"does it look fine?"** Brennan put the objection precisely, and it turned out to be the hinge of
the whole day:

> "bpp+ in its current format assumes that more bits is essentially always better and less is always
> worse, on a curve. But the thing is for some films more bits really DOESNT make the film better,
> because if we the humans can't see a difference then it doesnt matter."

and

> "if I can see intense banding, then its not a 110 even if the CF compression and encoding
> experiment says it is."

Both are now backed by measurement on named titles. **Dune (2021)** scores 110 and bands at 4.99,
well above the visibility threshold, on a clean responsive ladder (S −0.60, R² 0.996) — so the
banding is caused by its bitrate and a bigger file would genuinely fix it. It is not a 110.

The framework in one line:

```
m = (T / L)^(1/S)                 bitrate multiplier that brings an artifact to its visible threshold
BPP+_implied = BPP+ / sqrt(m)     because BPP+ IS sqrt(bpp/target) — no invented constant
```

`m > 1` pulls the score down, `m < 1` pushes it up. **Combine across artifacts by MAX, never sum** —
that is what makes correlated detectors safe, and it answers Brennan's *"cause yeah some will
correlate"* structurally instead of by tuning weights. If blocking and banding both demand 1.4×, the
answer is 1.4×, not 1.96×.

## The breakthrough: the relevance gate

The upward direction refused to work all day. Every rule that trusted "no artifact detected" ended up
raising most of the library — the same failure that once sent **Sunset Boulevard from 61 to 138**.

The reason was a misreading of the detector, and it is worth stating plainly because it will
generalise to every artifact we add:

> **Most films sit below the banding threshold for reasons that have nothing to do with quality.**
> Banding needs a smooth gradient to appear in. A grainy film reading zero is not a film with bits to
> spare — it is a film where banding was never the failure mode, because grain dithers the gradient
> away.

So **absence of an artifact only counts as evidence where that artifact was the expected way to
fail** — and the content tells us which films those are. Measured over the 247 units with a banding
reading:

```
SMOOTH tercile (cx < 0.128)    23% band visibly    <- banding IS the failure mode here
MID                            13%
GRAINY tercile (cx > 0.191)    11%                 <- a null here proves nothing
```

This is Brennan's own covering-set argument, executed with **one** calibrated detector rather than
waiting for all of them:

> "If we can create a class of artifacts where a given film is quite likely to have atleast one if
> its compressed, then the absence of all or most of them CAN be a signal that we can bump up bpp+."

## What it finds, at library scale

**Over-scored — green, but visibly banding:**

```
Dune (2021)                     BPP+ 110   banding 4.99   cx 0.051   R 1.19
E.T. the Extra-Terrestrial      BPP+ 123   banding 3.89   cx 0.098   R 1.52
Once Upon a Time in America     BPP+ 107   banding 3.87   cx 0.058   R 1.20
```

**Under-scored — red, smooth content so banding *was* expected, and it is not there:**

```
Forgetting Sarah Marshall (2008)   BPP+ 64   banding 0.304   cx 0.123   R 0.57
A Man Called Otto (2022)           BPP+ 67   banding 0.660   cx 0.116   R 0.61
```

Those two are the interesting ones: **R 0.57 and 0.61** means our own supply measure calls the source
starved — and starved *smooth* content is exactly what should band. It does not. That is Brennan's
suspicion (*"I bet at 5GB-10GB they actually look fine for humans"*) with names attached.

## And an independent, measured version of the same thing

The 12-film ladder was selected by spreading across complexity, so it is an unbiased draw. Asking
what each film *actually reads* after a real 30% bit cut — a rung that was encoded and measured, no
curve fitting:

```
TOO HARSH — scored <75, still not visibly banding at 0.7x bits:
  The Man Who Knew Too Much (1956)   BPP+ 55   banding@0.7 = 19% of threshold   <- the strong case
  Mission: Impossible (1996)         BPP+ 61   banding@0.7 = 93%                <- marginal
  Jay Kelly (2025)                   BPP+ 72   banding@0.7 = 88%                <- marginal

TOO KIND — scored >=100, visibly banding at its own bitrate:
  Marty Supreme (2025)               BPP+ 102  banding@1.0 = 5.13
```

**3 under-scored, 1 over-scored on an unbiased draw of 12**, and the under-scored side is the larger
one. Only The Man Who Knew Too Much is a *strong* case at 19% of threshold; the other two sit close
enough that a slightly bigger cut would tip them over. Say so when quoting this.

**BPP+ is still right on average** — correlation with measured banding is −0.50 on that sample. This
is a set of specific errors in both directions, not a systematic inversion.

# PART 1B — THE PUSHBACK THAT PRODUCED ALL OF THIS

**Read this section before trusting anything in Part 1.** Every result above exists because Brennan
rejected a conclusion I had already written down. Four times today I reported a negative result, and
four times the negative was an artefact of how I had framed the test. This is not politeness — the
specific corrections are load-bearing, and a cold reader who skips them will re-run the same wrong
tests.

## Challenge 1 — "Is this actually a failure mode?"

I reported that grain masking banding was a **failure**, and that the correction promoting grainy
starved copies proved the framework was broken. He pushed back:

> "Is this actually a failure mode? Or is this an indicator that those grainy films are actually
> looking pretty good and deserve to be scored higher?"

**He was right and my wording was wrong.** CAMBI reading 0.000 on Sunset Boulevard is *correct* —
there is no visible banding, and a dithered gradient genuinely looks better than a posterised one.
The detector is not failing. What fails is the inference *"no banding therefore enough bits"*,
because a grainy starved copy fails through a different artifact — grain boiling (§9.1), which is
exactly the Easy Rider case where BPP+ said 78 and Brennan said "a 60ish, or even lower like a 40".

**What it changed:** the whole framing moved from "the measurement is wrong" to "the measurement is
right and incomplete", which is what made the covering-set idea possible.

## Challenge 2 — the proxy is not the reference

I had been reporting every test as *"does the artifact residual add anything **on top of bits**?"*.

> "bpp IS supposed to answer if a redownload is worth it. Like if increasing the bits DOESNT improve
> the viewing experience... then our perception of the film being bit-starved is wrong, and its a
> higher bpp+ than we thought it was."

> "fundementally if I can see intense banding, then its not a 110 even if the CF compression and
> encoding experiment says it is."

> "I feel like we looked too hard for correlations between this new idea and the old model, assuming
> that the old model is perfect already, but the point of blending in artifact scores is to improve
> on the model for the cases when its final number geniunely gets it wrong."

**This is a genuine methodological error on my part, not a difference of opinion.** Partial-correlation
tests of the form "does X add beyond bits" treat bits as the reference and the artifact as the
challenger. For the disagreement cases — the entire point of the exercise — that is backwards.

**What it changed:** I stopped scoring the artifact against BPP+ and started looking for cases where
they disagree and asking which one is right. That is what produced the two screens in Part 1.

## Challenge 3 — a covering set, not all artifacts

I had argued the upward direction needed *every* artifact measured, and was therefore blocked
indefinitely.

> "I think we can do a reasonable job of closing the gap to 'all artifacts'. If we can create a class
> of artifacts where a given film is quite likely to have atleast one if its compressed, then the
> absence of all or most of them CAN be a signal that we can bump up bpp+, even if only by a bit.
> Cause I do have a suspicion that some of our files are being treated more harshly than they should
> be."

**This is the single most productive idea of the day**, and it is measurable rather than
philosophical. Two things followed immediately:

- **Coverage already passes.** Cut 30% of the bits from each of the 12 ladder films and *zero* of
  them fail to trip at least one detector. "We need all artifacts" was too pessimistic.
- **The relevance gate.** You do not need every artifact if you can tell which artifact was the
  relevant one for a given film — and complexity tells you that. This is the mechanism behind every
  upward result in Part 1.

His suspicion about harshly-treated files was also directly confirmed: The Man Who Knew Too Much,
BPP+ 55, grainiest film in the ladder set, still at 19% of the visibility threshold after losing
another 30% of its bits.

## Challenge 4 — "I dont believe we dont have a real result"

This is the one that matters most. I had reported the CVQAD null and the outlier-driven slope result,
and concluded the upward direction had no support.

> "hold up hold up I dont believe we dont have a real result (IE both up and down based on
> artifacts). Keep analyzing the data"

**He was right, and I would have stopped.** Two things came out of continuing:

1. **The relevance gate applied at library scale** — 3 over-scored, 2 under-scored, both directions,
   from measurement, with a principled gate.
2. **A measured, non-extrapolated version.** Asking what each ladder film *actually reads* at the
   0.7× rung — a level that was really encoded and really measured — gives **3 under-scored and 1
   over-scored on an unbiased draw of 12**. No curve fitting, which is the objection that had blocked
   the upward direction all day.

The lesson to carry: a null from one framing is not a null. Both of my negatives (CVQAD, and the
slope-predicts-quality test) were real *as stated* — and both were answering a question narrower than
the one being asked.

## Challenge 5 — the blending formula is open

> "each of these artifact detectors adjust/scale/dial the bpp+ #, but how they do it, the blending
> formula we use is up for discussion. Cause yeah some will correlate"

He accepted winner-takes-it as the shape but flagged correlation as the risk. That produced the
bits-equivalent formulation and **`max` rather than `sum`** — under a max, correlated detectors
*cannot* double-count, so the risk is removed structurally instead of by tuning weights.

## Where I was right to hold a line

Two places, recorded so they are not re-litigated in the other direction:

- **The upward direction genuinely does need more evidence than the downward one.** Finding a flaw
  proves a flaw; *not* finding one only proves something if the panel covers the ways a file can
  fail. That asymmetry is why upward moves are off by default in the lab, and Brennan's covering-set
  idea is the route through it rather than a refutation of it.
- **The cross-film residual really is dead** (§10.5d) and should not come back. The per-film ladder
  is not a softer version of it — it is a different measurement that does not share the failure mode,
  because a film is compared only against re-encodes of itself and its own grain cancels.

# PART 3 — WHAT WAS MEASURED TODAY

## 3.1 The detectors are graded, and it needed no labels

`scripts/grade-detector.js`. Split-half over per-clip readings, Spearman-Brown corrected. The unlock
is that grading a detector needs *repeated readings*, not a subjective label — and `probe-film.sh`
computed those all along, then averaged them away.

```
detector       n   clips  split-half  S-Brown   vs cx   vs BPP+   vs log bpp   vs res
blockMean     71    9.0     0.856      0.922   -0.000   +0.080     +0.063     +0.167
blurMean      71    9.0     0.367      0.537   -0.233   -0.009     -0.167     +0.078
cambi        247    8.0     0.643      0.782   -0.208   -0.347        —          —
complexity   256   17.7     0.915      0.955      —     -0.365        —          —
```

**`blockMean` is the most reliable artifact detector we have** — more reliable than CAMBI, which
shipped — and passes every runnable degeneracy test.

Two gaps, both tracked: the **luma test could not run** (2 of 71 units carry a luma reading; luma is
the axis `gShare` died on at −0.885), and **no visibility threshold exists**.

This does **not** contradict the 2026-08-17 kill. That killed blockMean as a *score term*; grading a
*detector* is a different question.

## 3.2 Reliability is not enough — the ladder is the discriminating test

A detector of frame structure would grade 0.92 too, because films differ consistently in edge
content. The question that separates an artifact from a content statistic is whether the reading
**moves when bits are removed**. `banding-ladder.js` now chains `blockdetect`/`blurdetect` ahead of
libvmaf, so all three come off one decode and the expensive starvation encode is shared.

```
                    S band   S block   S blur      full-range swing (1.3x -> 0.7x)
median               -0.84    -0.105   -0.029      banding  x1.74  (max x6.07)
negative on          11/12     12/12    12/12      blocking x1.09  (max x1.26)
mean R^2              0.90      0.86     0.98      blur     x1.02  (max x1.03)
```

**Blocking responds on every film, in the right direction, R² 0.86** — it is a genuine artifact
detector. But the response is small: 9% across a near-2× bitrate range against banding's 74%.

**Blur is inert** — 2% swing, 0.537 reliability. Retire it.

## 3.3 Level and slope are different facts — replicated three ways

```
our library ladder (n=6)       spearman -0.886
new 12-film ladder (n=12)      spearman -0.741   (pearson -0.860)
CVQAD, real masters (n=18)     spearman -0.816   (pearson -0.827)
```

How much artifact a film **has** is close to the inverse of how much it **responds to bits**. Robust
to subsetting (−0.798 on well-fit sequences only; −0.687 dropping the highest-leverage one).

**And it answers Brennan's question from the 21st** — *"How could we ever possibly tell baked in? We
dont have the source."* You do not need the master. You need the derivative: if compressing further
does not increase the artifact, it was already there.

## 3.4 The cross-film residual is dead — do not revive it

At n=247, applying the residual as a shift moves 78 of 247 films ≥10 points at k=0.15 and sends
**Sunset Boulevard 61 → 138** (313 at k=0.30). Two causes: grain *prevents* banding, and the
`log(cambi)` floor sends a zero-banding film to −9.2 so the least informative films dominate the fit.
Written up as `BPP-PLUS.txt` §10.5d.

## 3.5 CVQAD — a null, and a limitation I should have caught earlier

The decisive test at 124 clips / 27 sequences:

```
                                    Bradley-Terry    MOS
  bits alone vs label                    +0.643     +0.703
  POOLED  residual vs label-after-bits   +0.037     +0.073
  WITHIN  residual vs label-after-bits   -0.137     -0.070   <- the test
```

Sign correct, magnitude below the 0.15 floor. Head-to-head, adding banding to a bits-only model made
prediction **worse** (LOO rmse 0.8363 → 0.8465).

**But CVQAD's bitrates span 90 kbps to 39 Mbps — a 400× range.** At that spread bits explain nearly
everything by brute force (within-sequence score sd 2.04, only 0.83 left after bits). Our library
lives in a narrow band near transparency where bits are nearly flat. **CVQAD is the wrong instrument
for that question** — and the right one for a different question, see Part 4.

Also falsified: the claim that banding slope predicts how fast quality rises with bits. Pearson
−0.483 across 18 sequences, but **one sequence carried all of it** — drop crowd-run-2020 and it goes
to +0.189. Spearman was +0.067 throughout.

## 3.6 A trap in the CVQAD corpus that would have voided everything

Every distributed clip is an **HEVC re-encode at 10–49 Mbps** of the x264-compressed video, not the
x264 bitstream. `basketball-2021/fast/x264_100` reads 10,524 kbps in its container; the CSV's
`real_bitrate` is **90 kbps**. A factor of **117**. Bits must come from the CSV; `renderKbps` is kept
for diagnostics only and must never enter a model. Caveat: the HEVC pass could itself smooth a little
banding, which biases the test *toward* null — so a positive result is conservative, a null is not
proof of absence.

## 3.7 The grain blocker is solved

`scripts/find-static-bright.js`. Blurs hard **before** differencing, so grain is filtered out and only
camera displacement survives — that is what separates "still" from "grainy" when both raise
frame-to-frame difference. On **Easy Rider**, the film that failed as a control because *245 of 249
frames were dropped as camera motion*:

```
8 of 24 candidates are still AND bright
probe-noise-origin at 00:51:20  ->  cuts/motion dropped 0
```

**And a correction to something I claimed earlier today:** the "slope sign separates grain from
compression noise" idea is **not** the breakthrough. §9.1 already has a better discriminator, built
and validated at n=2 — `iRatio` (grain renews every frame; compression error freezes in a GOP) and
`gridRatio` (compression correlates with the 8×8 transform grid; grain does not). Both come from one
pass; the ladder idea needs five encodes to recover less.

**New finding: `iRatio` is hard to sample.** Keyframes in these files are placed at *scene changes*
(irregular spacing: 3071.78, 3081.79, 3087.21, 3088.92…), and scene-change I-frames are exactly the
ones that must be discarded — that is the documented Spirited Away trap. Periodic I-frames are ~10 s
apart and a still window rarely lasts that long. **`gridRatio` has no such problem** — purely spatial,
needs no I-frame. Easy Rider read **1.087**, against baselines of Star Wars 1.165 (artifacts) and No
Other Choice 0.995 (clean). That independently confirms §9.2's standing recommendation to test
gridRatio first.

## 3.8 Detector-panel coverage already passes

Cut 30% of the bits from each of the 12 ladder films and ask whether *anything* moves:

```
films where NOTHING moved (<1.15x on every detector): 0 of 12
```

Every film tripped at least one detector. "We would need all artifacts" was too pessimistic — you
need enough that *something* fires, and something already does. What is missing is not more
detectors, it is **thresholds** for the two we cannot yet read.

# PART 6 — THE TRAPS, FOR A COLD START

1. **Ladder absolutes are not comparable between runs.** Clip offsets are `T = start + span*k/CLIPS`,
   so changing the clip count changes which scenes are sampled, and banding is violently
   scene-dependent — The Big Sleep read 0.0859 at level 1.0 with 4 clips and 0.00716 with 3. Only
   ratios *within* one run are meaningful. This is why the fitted **slope** travels between runs and
   the **level** does not, and why predicting slope from the *nightly* level (R² 0.363) beats
   predicting from the ladder's own (R² 0.251).
2. **Never compare a ladder absolute against the nightly job's absolute.** E.T. reads 3.885 nightly
   and 2.150 at level 1.0 in its ladder. Different scenes, both correct.
3. **`log(max(cambi, floor))` has now caused three separate failures.** Any new artifact that can read
   near zero needs a floor decided *before* it enters a model.
4. **A grainy film reading zero banding is not evidence of anything.** See the relevance gate.
5. **CVQAD clips are HEVC renders.** Bits from the CSV, always.
6. **Reliability is necessary, not sufficient.** A misspecified detector repeats itself too.
7. **Never `pkill`/`pgrep` with a pattern that matches your own shell.** Has happened three times.
